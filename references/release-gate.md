# 0.2.0 到 1.0 的发布门槛

`0.2.0` 表示内容工作流、封面冻结、预览、账本和官方 API 状态机已完成离线验证；公众号后台手动草稿流程已实机验证，但 BrowserSkill 自动草稿适配器尚未形成独立端到端证据，更不是“已完成浏览器自动发布”的对外承诺。

升至 `0.9.0` 前，BrowserSkill 草稿构建必须通过完整 CLI 实测：进入公众号编辑页、账号/标题/摘要/正文/封面回读、公众号原生图片库上传与裁切、保存草稿、按稳定标识重新打开草稿的字段回读，以及终态无自有会话。保存派发前必须有持久化意图；响应丢失、同名旧稿、多匹配或字段漂移一律不能报成功。

升至 `1.0.0` 前，除完整离线与对抗测试外，还必须在 macOS 与 Windows 各完成：含内文图片的草稿精确回读、明确确认后的一次公开文章发布、作品列表的标题/时间/链接验证，以及终态无自有会话或空白页面。群发路径、重复发布、错误账号、凭据泄漏、可见 `about:blank` 或无法解释的 uncertain 任一项都阻断发布。

性能验收只计算“文章与封面已准备、账号已登录”后的自动操作：目标不超过 60 秒，硬预算 120 秒；接管确认另行统计。每次验收必须返回阶段耗时、人工等待、字段验证和清理结果，不能将人工排障混入自动耗时。
