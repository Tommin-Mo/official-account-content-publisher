# BrowserSkill 浏览器后端

BrowserSkill 是预登录公众号账号的默认后端。它不读取、导出或打印 Cookie，也不允许群发。

## 会话与写入门槛

- `doctor` 只读检查 BrowserSkill daemon、扩展和唯一浏览器连接；写入前会额外校验锁定的 `bsk 0.2.0` 运行时。
- `deliver` 在创建任务前检查账号别名、BrowserSkill 连接、经过文件头与哈希校验的封面，以及当前路线实际支持的字段。
- 每项任务只拥有一个 BrowserSkill 会话和一个编辑页。草稿已确认后正常归还标签并停止会话；已填写但未确认保存时保留编辑页，避免丢失内容。
- BrowserSkill 会先在后台创建 Agent Window，再立即导航。完成导航后首个用户可见页面必须为公众号编辑页；若仍为 `about:blank`、账号不确定、控件多匹配、验证码或“群发”控件则停止。后台瞬时 URL 仅作诊断，不能覆盖已完成的目标路由验证。
- 封面通过公众号自身的“图片库上传 → 裁切确认”流程写入。Skill 使用 BrowserSkill 的原生文件输入上传；封面字节不进入任务账本、日志或页面脚本。

当前适配器只开放“保存草稿”路径，自动适配器仍待独立端到端验收。保存命令派发前会先持久化提交意图；派发后任何响应丢失均为 `draft_uncertain`，不能重试。草稿验证要求保存前同标题基线、稳定草稿标识、重新打开编辑页后的标题、摘要、正文与封面回读；页面提示和预览只能辅助判断。任一环节不能唯一确认时返回 `draft_uncertain`，不会把页面跳转当作成功。

`verify <task_id>` 是只读恢复：它只按原任务保存的草稿标识与字段哈希重新打开草稿核对，不创建草稿、不点击保存，也不以本地状态猜测线上成功。

自动操作的统一预算为 120 秒；接管标签的人工等待单列，不挤占自动操作预算。结果和失败诊断只记录阶段耗时、调用次数与清理状态，不记录正文、Token、Cookie 或私人路径。一次运行最多申请一次标签接管；连接失败不会反复重开会话。

当前浏览器路线只支持标题、摘要、正文、封面和默认开放留言。作者、原文链接、关闭留言或仅粉丝留言会在启动浏览器前明确阻断，不会静默忽略。

## 发布限定

浏览器公开发布尚未完成单次点击和作品列表回读验收，因此当前被阻断。任何“群发”“发送给粉丝”“群发消息”均为永久拒绝项。
