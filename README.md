# 公众号内容与自动发布助手

把一个主题、资料、数据或既有文案，整理为适合微信公众号阅读与投递的长文工作流。

它把“写一篇文章”拆成可核查的环节：明确文章定位、整理来源与事实、把数据转成有机制和方向的观点、完成公众号排版与移动端预览、冻结正文后准备封面，再交付为草稿或进入明确确认后的发布流程。

## 它适合做什么

- 行业分析、深度观点、教程、案例复盘、活动招募、互动引流、快讯与访谈。
- 对已有文案做事实审查、结构排版、风格润色或原文投递准备；默认不会擅自改写。
- 将数据与主题、比较基准、可能机制、反方解释、限制和行动方向一起呈现，避免只有数据评论、没有分析。
- 用统一的语义内容包生成公众号安全 HTML，并提供 375px 和 393px 移动端预览。
- 在正文通过审查后生成封面提示词、校验封面比例和文件完整性；封面与正文版本绑定。
- 为已登录的公众号后台提供受约束的草稿投递实验路线：不群发、不批量发送、不自动删除。

## 关键约束

- 默认交付是草稿；公开发布必须由用户明确确认。
- “发布文章”不等于群发。任何“群发”“发送给粉丝”“删除”控件都在拒绝清单内。
- 写作、审查、预览和封面计划不会打开浏览器或调用公众号接口。
- 账号、标题、摘要、正文、封面和写入结果必须回读核对；结果不明时会停止在不确定状态，避免重复提交。

## 当前状态

这是 **0.2.0 内部候选版**。内容包、事实与洞察门禁、排版、预览、封面冻结、任务状态机和离线对抗测试已经具备。原生 BrowserSkill 草稿执行器也已纳入源码，但仍需在更多真实账号与页面版本上完成独立端到端验收；因此它不应被当作已经稳定的生产级自动发布工具。

## 快速开始

请先阅读 [SKILL.md](SKILL.md)。日常对话可直接这样开始：

> 把这个主题写成一篇公众号行业分析，先核对数据、反方观点和移动端排版。

只给标题或一句想法时，工作流会先确认内容类型、读者和目标，避免把快讯、宣传稿或互动引流误写成深度文章。

本地检查：

```bash
python3 scripts/cli.py doctor
python3 -m unittest discover -s tests
python3 scripts/audit.py
```

## 运行边界

- 浏览器自动化依赖单独安装并连接的 Tencent BrowserSkill；本仓库不包含浏览器扩展、二进制、Profile、Cookie 或配对数据。
- 公众号 API 是可选通道，需要用户自行通过安全凭据提供权限；密钥不写入内容包、日志或仓库。
- 真实草稿或发布应使用测试账号与非敏感内容验收。出现登录失效、账号不唯一、验证码、页面字段不唯一或结果不明时，流程会停下请求人工处理。
